## Summary

- Today the agent's only advisory source is what the repo's own gate targets print: an advisory supplied from outside the repo — a task filed with an `advisory:` frontmatter block — has no path into planning, so it can never drive a fix and its absence is silent.
- This spec lets a task carry one externally-supplied advisory (id, package, fixed version, source); planning reads it and validates it in Go, and admits it into the same findings table the model classifies, so the advisory drives a targeted dependency fix.
- Spec 002's anti-fabrication guard is untouched: the model still never authors an advisory ID, and the table — now fed from two Go-verified provenances — stays the only source of IDs.
- ai_review gains the proof that is missing today: for an external advisory it resolves the package's installed version on the branch and asserts it is at or above the fixed version. Green gates alone are not evidence for an advisory the repo's scanners never reported.
- A malformed advisory is rejected loudly and never silently dropped; a task without an advisory block behaves exactly as today.

## Problem

`github-update-go-agent`'s planning step builds its ground truth from the repo's own gate output (spec 002): Go runs the repo's gate targets, parses the rows into a findings table, embeds that table in the planning prompt as the only source of advisory IDs, and validates every plan ID against it. An advisory that originates outside that loop — an operator or a security feed filing a task with the advisory in the task's frontmatter — has no path in: nothing reads the field, the ID never enters the table, and the model is forbidden from adding an ID it was not handed, so the advisory cannot be planned, cannot be fixed, and its absence is silent. The second half of the gap is in ai_review: `vulns_clear` is set from the repo's gate re-run coming back green, which proves the repo's own scanners pass — not that an externally-supplied advisory cleared. An external advisory may be absent from that scanner output entirely (a transitive dependency, a different scanner configuration, an allowlist or suppression scope), so widening the table without a targeted check would let an external advisory be certified on evidence that never mentions it.

## Goal

A task carrying an `advisory:` block plans and executes a targeted fix for that advisory, and the run reaches the operator's inbox only when the advisory's package is actually at or above its fixed version on the update branch — verified in Go, independently of the repo's scanners. The model's role is unchanged: it classifies rows Go handed it and never authors an ID. End state: an externally-supplied CVE cannot be silently ignored, cannot be parked as if it were an ordinary scanner finding, and cannot be reported fixed on evidence that does not mention it.

## Assumptions

- The `advisory:` block is written by a producer outside this repo (a watcher, a security feed, or an operator filing by hand). This spec defines the frontmatter contract and the agent's behavior; it does not build the producer.
- The repo's module graph is resolvable inside the agent pod: the gate runner already inherits the full pod environment (GOPROXY/GOPATH/HOME), which is what lets repo Makefiles run scanners via `go run tool@version`.
- An external advisory always carries a real fix version — an advisory with no fix is not representable in the block (it is rejected at admission), so the external path is a fix path and never a park path.
- The task frontmatter reaches the agent through the platform's normal task content; the block rides the existing frontmatter mechanism with no new transport.

## Non-goals

- Do NOT relax spec 002's anti-fabrication guard. `validatePlanAgainstTable` stays a verbatim membership check against the captured table; this work widens the table's trusted source set, never the validator.
- Do NOT let an external advisory park the task — an advisory with no parseable fixed version is malformed input, rejected loudly at admission, never a park.
- Do NOT change the gate-green check for rows the repo's own scanners reported; gate-greenness stays the whole vulns verdict for those rows.
- Do NOT build a producer: no feed poller, no watcher change, no new service. The frontmatter block is the interface.
- Do NOT change the `## Plan` / `## Result` / `## Review` JSON contracts or the `ReviewChecks` key names and meanings.
- Do NOT add config fields, opt-out flags, tunable thresholds, or a per-repo trust switch — invariant; if a future consumer demands variation, that is a separate spec.
- Do NOT add a list form or multiple advisories per task — one advisory per task; a second advisory is a second task.
- Do NOT add a stdlib-specific version-resolution path — an advisory naming the Go standard library has no module-graph version, so the per-advisory check fails closed and the note names the package; making stdlib advisories auto-verifiable is a separate spec.
- Do NOT add loop-bounding or a retry cap for a permanently-failing review — that failure class is the platform's existing behavior, tracked separately.
- Do NOT change the review's other checks (PR state, changelog, tag) or the `## Your Move` operator-action block.

## Desired Behavior

1. Planning reads the task frontmatter's `advisory` block in Go at the findings-table construction site — after gate-target detection, before the first gate target runs — and admits it as one row of the table whose scanner label is `external:<source>`. The block is a single mapping with the keys `id`, `package`, `fixed_version`, `source`; when the block is absent nothing changes.
2. Admission is validated before the row enters the table: the ID matches the existing advisory-ID shape (`GO-<year>-<n>`, `CVE-<year>-<n>`, `GHSA-xxxx-xxxx-xxxx`), `package` is non-empty, `fixed_version` parses as a Go module version, and `source` is non-empty. Any failure ends the run with `needs_input` naming the field and the offending raw value — the same-input-same-answer class per the platform status taxonomy, matching the existing missing-frontmatter escalation — and never admits a partial row.
3. The table the model receives has two provenances and says so: the `## Scanner Findings` preamble names the Go-captured gate output and the validated external advisory, and keeps the invariant sentence that this table is the only source of advisory IDs — that sentence survives in both carriers, the preamble the planning step builds and the planning prompt module. The model's contract is otherwise unchanged: it classifies rows and never authors an ID.
4. Duplicate IDs collapse: when the advisory's ID also appears in gate output, exactly one row survives, and the row carrying a non-empty fixed version wins (the repo's scanner row when it carries one, the advisory row when the scanner row carries none), and the surviving row keeps its own `scanner` label — `external:<source>` when the advisory row wins, the scanner-derived label when the scanner row wins — so the model sees one row per ID and the plan's fixed version is a real value.
5. Plan validation is untouched: every `vulns[].id` must appear verbatim in the widened table, and an ID present in neither provenance fails the run loudly with the ID named. Nothing is parked on it.
6. ai_review derives the external advisory set from the task frontmatter — the same validated parse, never from `## Plan`, `## Result`, or the model's scanner labels — and, on the fresh worktree at the branch, resolves the installed version of the module providing the advisory's package in the repo's module graph. The resolution covers a package that is only an indirect dependency: the package path lives inside a module that is not a direct requirement, and no `go.mod` names that package path (module files list module paths, not package paths), so reading the root `go.mod` text is not a substitute for the graph. A block that fails validation at review time — the frontmatter was edited between planning and review, for example — fails the review closed: `vulns_clear: false`, `approved: false`, `failed`, and a note naming the offending field and its raw value. The review has no admission step, so it never escalates `needs_input` and never skips the check.
7. `vulns_clear` is true only when the gate re-run is green AND every external advisory resolves to an installed version at or above its `fixed_version`. A shortfall, or an undeterminable one (package absent from the module graph, unparseable version, resolution command failure), sets `vulns_clear: false`, fails the review closed (`approved: false`, `failed`, no `## Your Move`), and writes a note naming the advisory ID, the package, the installed version and the required fixed version. For rows the repo's own scanners reported, gate-greenness remains the whole verdict.
8. A task without an `advisory` block behaves exactly as today in both phases: planning's table is the gate output alone, and the review's `vulns_clear` rides the gate re-run.

## Constraints

- Spec 002's invariants hold unchanged: the model never authors an ID, `validatePlanAgainstTable` remains a verbatim membership check against the captured table, and the park path (`needs_input` naming the verbatim row plus the suppression surfaces) is untouched.
- The `advisory` frontmatter block shape is frozen: a single mapping with the keys `id`, `package`, `fixed_version`, `source`. Unrecognized extra keys are ignored; the four documented keys are required and non-empty. The one `advisory` key is the whole interface — a second advisory written under a different key name is not the block and has no effect; two advisories in the `advisory` value (a list) are rejected at admission.
- `PlanOutput` / `PlanVuln` / `ReviewOutput` / `ReviewChecks` serialized keys keep their names and meanings; the external row rides the existing `scanner` field as `external:<source>`, so no new plan or review field appears.
- The review's checks stay derived from independent re-execution on a fresh worktree: the per-advisory check never reads the plan's or the result's claims about the fix, and it runs in Go, never as a model instruction.
- The existing suppression pipeline applies to the admitted row unchanged (design D4): an advisory whose ID the repo already suppresses is filtered out of the table like any other row, the plan then carries no fix for it, and the review's per-advisory check fails closed with a note naming the ID and both versions — the operator clears the ignore entry or drops the advisory, then re-delegates.
- The existing scanner-vs-scanner duplicate behavior (two gate targets emitting the same ID) is unchanged; the dedupe covers only the external-versus-scanner collision.
- The module-version resolution is bounded by a hard timeout, matching the existing bounded-command convention for Go invocations in this repo, so a hung toolchain fails loudly instead of consuming the Job budget.
- Error handling follows the repo's `github.com/bborbe/errors` convention; no `fmt.Errorf`, no `context.Background()` in `pkg/`.
- Gate target names still pass `gateTargetRegexp` before reaching `make` argv — unchanged.
- No new module dependencies: module-version parsing and ordering use the `golang.org/x/mod` module already required by this repo.
- All existing tests pass except where this spec changes behavior explicitly; `make precommit` and `make test` stay green.

## Security / Abuse Cases

- **Who controls what.** The `advisory` block is task frontmatter, so it sits behind the same trust boundary as `repo`, `clone_url`, and `ref`: anyone who can file a task for this agent can set it. That boundary already lets a filer point the agent at an arbitrary repo and branch; the block adds the ability to name a dependency and a version inside that same boundary.
- **What reaches a command.** The package and version strings travel the same path scanner-derived package strings already travel (into the model's targeted `go get <package>@<version>` instruction during execution). The advisory path introduces no new command surface, and the fix lands as a diff in a PR that a human still merges — the agent never merges.
- **What is validated.** The ID must match the advisory-ID shape, the package must be non-empty, the fixed version must parse as a Go module version, and the source must be non-empty — all before the row is admitted, so a malformed block cannot reach the model or the plan. A block that is malformed at review time fails the review closed instead of being skipped.
- **What fails closed.** A package the module graph cannot resolve, an unparseable installed version, or a failing resolution command never yields `vulns_clear: true`, so an advisory cannot be certified by absence of evidence. The per-advisory check never trusts the model's or the result's claims about the fix.
- **What can hang or race.** The module resolution is a bounded Go command with a hard timeout, and the review's workdir is a per-run temporary clone, so two runs of the same task cannot race on shared state.
- **No new secrets.** The block carries no credentials, and nothing new is logged beyond the advisory ID, package, versions, and source label.

## Do-Nothing Option

The agent keeps a single advisory provenance. An externally-supplied CVE can only be handled by hand-editing a repo's `go.mod` or by the operator's own PR — a per-advisory manual tax, and the agent's unattended sweep neither sees the advisory nor reports that it skipped it. Any future external feed has nothing to file against. Meanwhile `vulns_clear` keeps its meaning as a repo-scanner proxy, so an ingestion added later without the review-side check would certify external advisories on evidence that never mentions them — the silent false-fix class spec 002 was written to prevent, one layer up. Doing nothing is acceptable only while every advisory of interest is one the repo's own scanners report, which is exactly the assumption an external advisory source exists to break.
