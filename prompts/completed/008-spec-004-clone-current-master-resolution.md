# Resolve the clone ref to the repo's current default-branch HEAD at run start

<summary>
- The planning phase now resolves the repo's current default-branch HEAD at the start of a run and clones that SHA instead of the stale SHA pinned in the task frontmatter at filing time.
- The execution phase does the same at its own run start, so the go-version bump and its precommit gate always run against the repo's current tooling — the exact failure the spec fixes (export-data mismatch on pre-Go-1.27 tooling) cannot recur.
- The original pinned SHA stays in the task title/frontmatter completely untouched — it remains the provenance record and still names the deterministic work branch (`fix/update-go-<ref:7>`), preserving the crash-window replay guard.
- If resolving the current HEAD fails (network, auth, rate-limit, non-`master` default branch), the run stops with a `failed` result whose message names the resolution step and the error — it never falls back to executing on the stale pinned ref.
- A repo whose default branch is not `master` fails loud naming the actual branch, instead of silently bumping the wrong branch.
- The resolution is a new method on the existing `GitOps` seam, so it is exercised through the same fake seam the clone already uses — the pinned ref being "recorded, not used as the clone base" is asserted directly.
- Unit tests cover: resolved-HEAD clone in both phases, the no-fallback failure path in both phases, provenance preservation, and the real `git ls-remote --symref` boundary (including the non-master branch mismatch).
</summary>

<objective>
Make both the planning and execution phases of an "Update Go" task clone the repo's current default-branch HEAD — resolved at each run's own start — instead of the stale filing SHA, so the version bump and its precommit gate always run against the repo's current tooling, while the pinned SHA stays recorded for provenance and any resolution failure stops the run loudly rather than proceeding on a stale base.
</objective>

2. **Implement `ResolveDefaultBranchHead` on `osExecGitOps`** in `pkg/git/os_exec_git_ops.go`. The `--symref` output is two lines — `ref: refs/heads/<branch>\tHEAD` then `<sha>\tHEAD`:

   ```go
   func (g *osExecGitOps) ResolveDefaultBranchHead(ctx context.Context, cloneURL string) (string, error) {
   	// git ls-remote --symref <cloneURL> HEAD — returns the default-branch
   	// symref line (ref: refs/heads/<branch>\tHEAD) followed by the SHA line.
   	// #nosec G204 -- cloneURL is authed by caller from validated frontmatter
   	cmd := exec.CommandContext(ctx, "git", "ls-remote", "--symref", cloneURL, "HEAD")
   	cmd.Env = g.cmdEnv()
   	var stderr bytes.Buffer
   	cmd.Stderr = &stderr
   	out, err := cmd.Output()
   	if err != nil {
   		return "", errors.Errorf(ctx, "git ls-remote --symref HEAD: %s", redactToken(strings.TrimSpace(stderr.String())))
   	}
   	lines := strings.Split(strings.TrimSpace(string(out)), "\n")
   	if len(lines) < 2 || !strings.HasPrefix(lines[0], "ref: ") {
   		return "", errors.Errorf(ctx, "git ls-remote --symref HEAD: no default-branch symref in %q", string(out))
   	}
   	defaultRef := strings.Fields(lines[0])[1]
   	if defaultRef != "refs/heads/master" {
   		return "", errors.Errorf(ctx, "default branch is %s, expected refs/heads/master", defaultRef)
   	}
   	shaFields := strings.Fields(lines[1])
   	if len(shaFields) == 0 {
   		return "", errors.Errorf(ctx, "git ls-remote --symref HEAD: no SHA for default branch in %q", string(out))
   	}
   	sha := shaFields[0]
   	glog.V(2).Infof("git ls-remote --symref HEAD: default=%s head=%s", defaultRef, sha)
   	return sha, nil
   }
   ```

   Error paths (all must return a wrapped error, never panic): git binary failure → the redacted stderr error above; missing `ref:` line (e.g. detached-HEAD remote) → "no default-branch symref"; default branch ≠ `refs/heads/master` → the branch-mismatch error naming the actual branch (spec Failure Modes row 2); no SHA line → "no SHA for default branch".
