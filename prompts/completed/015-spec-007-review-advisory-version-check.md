# ai_review verifies an external advisory against the branch's module graph

<summary>
- The review step stops treating a green gate re-run as proof that an externally-supplied advisory cleared.
- For a task that carries an advisory block, the review now resolves the advisory's package in the branch's module graph and requires the installed version to be at or above the advisory's fixed version.
- The check is driven by the task frontmatter, never by the plan or the result, so a plan that silently omits the advisory still gets caught.
- A package the module graph cannot resolve, an unparseable installed version, a failing resolution command, and a version shortfall all fail the review closed with a note naming the advisory, the package and the versions.
- An advisory block that no longer validates at review time fails the review closed too — it is never skipped and never escalated as a question.
- Tasks without an advisory block behave exactly as before: the gate re-run remains the whole vulnerability verdict.
- The resolution is a bounded Go command with a hard timeout, so a hung toolchain fails loudly instead of consuming the job budget.
</summary>

<objective>
Make `vulns_clear` honest for an advisory the repo's own scanners never reported: derive the external advisory from the task frontmatter, resolve the installed version of the module providing its package on the fresh worktree at the branch, and require that version to be at or above the advisory's fixed version — so an external advisory can never be certified on evidence that does not mention it.
</objective>

1. **Create `pkg/module_versions.go`** in `package pkg`, with the 3-line BSD copyright header copied verbatim from `pkg/review_output.go`. It holds the module-graph seam and the two pure helpers around it.

   ```go
   // moduleResolveTimeout bounds the module-graph listing command. The listing is
   // a read-only query over an already-resolved graph, so it is far cheaper than
   // the bulk-update sequence (bulkUpdateTimeout, 8m) — but it is still hard: a
   // command that exceeds it is a resolution failure, reported and never retried.
   const moduleResolveTimeout = 2 * time.Minute

   // moduleListFormat is the `go list -m -f` template. Two whitespace-separated
   // columns, one row per module: the module path and its selected version (empty
   // for the main module).
   const moduleListFormat = "{{.Path}} {{.Version}}"

   // ModuleVersion is one module of a worktree's module graph with its installed
   // (MVS-selected) version. Version is empty for the main module.
   type ModuleVersion struct {
       Path    string
       Version string
   }

   //counterfeiter:generate -o ../mocks/module_resolver.go --fake-name ModuleResolver . ModuleResolver

   // ModuleResolver lists the modules of a worktree's module graph. It is the
   // seam the ai_review step resolves an external advisory's package through:
   // the installed version of a package lives in the module that provides it,
   // and that module may be an indirect requirement.
   type ModuleResolver interface {
       // Modules runs `go list -m -f {{.Path}} {{.Version}} all` in workdir under
       // moduleResolveTimeout and returns the parsed module list. A non-nil error
       // means the graph could not be read — the caller fails closed.
       Modules(ctx context.Context, workdir string) ([]ModuleVersion, error)
   }

   // NewOSExecModuleResolver constructs the production ModuleResolver.
   func NewOSExecModuleResolver() ModuleResolver
   ```

   `osExecModuleResolver` (private struct) implements `Modules` by mirroring `bulkUpdater.run` in `pkg/bulk_update.go`:

   - `ctx, cancel := context.WithTimeout(ctx, moduleResolveTimeout)` with `defer cancel()`.
   - glog a start line before the call and a done line after (`event=module_graph_exec_start` / `event=module_graph_exec_done`), carrying workdir, the command and the timeout — a resolution that never returns must be distinguishable from one never attempted.
   - `exec.CommandContext(ctx, "go", "-C", workdir, "list", "-m", "-f", moduleListFormat, "all")` with the same `#nosec G204` comment style as `pkg/bulk_update.go` and `pkg/gate_runner.go` (binary hardcoded, workdir is os.TempDir-rooted, remaining args are fixed literals).
   - On error: if `ctx.Err() != nil`, return `errors.Wrapf(ctx, ctx.Err(), "go list -m all exceeded %s", moduleResolveTimeout)`; otherwise `errors.Wrapf(ctx, err, "go list -m all in %s: %s", workdir, truncateTail(string(out), gateTailMaxBytes))` so the failing command's own words reach the note.

   Implement the two pure helpers in the same file:

   ```go
   // parseModuleList parses `go list -m -f '{{.Path}} {{.Version}}' all` output
   // into module rows. One row per non-empty line; the version column is empty
   // for the main module, which go list prints as a bare path. A line with no
   // fields is skipped. A module the parse misses simply never matches a
   // package, and the caller's fail-closed check catches it.
   func parseModuleList(output string) []ModuleVersion

   // moduleForPackage returns the module whose Path is the longest prefix of
   // pkgPath at a path-segment boundary, together with that module's installed
   // version. found is false when no module in the graph provides pkgPath — the
   // caller fails closed. Reading go.mod text is NOT a substitute: module files
   // list module paths, never package paths, so an indirectly-required module's
   // subpackage appears in no go.mod.
   func moduleForPackage(modules []ModuleVersion, pkgPath string) (ModuleVersion, bool)
   ```

   `parseModuleList`: split on `\n`; `strings.Fields` each line; `len(fields) == 0` → skip; `len(fields) == 1` → `ModuleVersion{Path: fields[0]}`; otherwise `ModuleVersion{Path: fields[0], Version: fields[1]}`.

   `moduleForPackage`: iterate the modules, skip an empty `Path`, and accept a module only when `pkgPath == m.Path || strings.HasPrefix(pkgPath, m.Path+"/")` — the `+ "/"` is the segment-boundary guard, so module `example.com/a` never matches package `example.com/ab/c`. Among the accepted modules keep the one with the longest `Path`; return `found=false` when none matched. The `+ "/"` guard and the longest-prefix rule are the load-bearing logic of this prompt — cover both directly in tests.

3. **Add `checkAdvisories`** to `pkg/steps_review.go`:

   ```go
   // checkAdvisories derives the external advisory from the task frontmatter and,
   // on the fresh worktree at the branch, resolves the installed version of the
   // module providing the advisory's package in the repo's module graph. It
   // never sets vulns_clear true — it can only clear it, so a satisfied advisory
   // can never certify a red gate. A shortfall, a package the graph does not
   // carry, an unparseable installed version, and a failing resolution command
   // all fail closed. An invalid block fails closed too — parseErr carries it, and the
   // note for it was already written by Run. The review never reads the plan's or
   // the result's claims about the fix, never escalates needs_input, and never
   // skips this check. A nil advisory with a nil parseErr means the task carries
   // no advisory block and nothing changes: vulns_clear rides the gate re-run.
   func (s *reviewStep) checkAdvisories(
       ctx context.Context,
       advisory *AdvisoryBlock,
       parseErr error,
       workdir string,
       checks *ReviewChecks,
       notes *[]string,
   )
   ```

   Behaviour, in this order:

   - `parseErr != nil` → `checks.VulnsClear = false` and return. Do NOT append a note here — `Run` already wrote it, and a second copy would duplicate the field/value text.
   - `advisory == nil` → return (no block, nothing changes).
   - `s.modules.Modules(ctx, workdir)`; on error → append the note below, `checks.VulnsClear = false`, return.
   - `moduleForPackage(modules, advisory.Package)`; `found == false` → append the note below, `checks.VulnsClear = false`, return.
   - `semver.IsValid(module.Version)` false → append the note below, `checks.VulnsClear = false`, return.
   - `semver.Compare(module.Version, advisory.FixedVersion) < 0` → append the note below, `checks.VulnsClear = false`, return.
   - Otherwise leave `checks.VulnsClear` exactly as `checkGates` left it (true only when the gate re-run was green).

   `semver` is `golang.org/x/mod/semver` (`semver.IsValid`, `semver.Compare`), part of the `golang.org/x/mod` module this repo already requires and imports.

   The four notes must be single-line strings appended to `*notes`, and each must name the advisory ID, the package, and the reason — so the operator can act on the note alone:

   - resolution failed → `"advisory " + advisory.ID + ": module graph resolution for package " + advisory.Package + " failed: " + err.Error()`
   - package not found → `"advisory " + advisory.ID + ": package " + advisory.Package + " is not in the module graph — installed version undeterminable"`
   - unparseable installed version → `"advisory " + advisory.ID + ": package " + advisory.Package + " resolved to module " + module.Path + " with unparseable installed version " + module.Version`
   - shortfall → `"advisory " + advisory.ID + ": package " + advisory.Package + " installed " + module.Version + " < required " + advisory.FixedVersion`

   Because `finish` maps any non-approved review to `AgentStatusFailed` with no `NextPhase` and `writeYourMoveSection` is only reached on approval, the fail-closed path already produces "no `## Your Move` heading" — do not add a second guard for it.
